# CSC（Currkill's Simple Command Language）

> 本项目的绝大部分代码由 **Deepseek Harness** 完成。

## 这是什么

**CSC** 是 Simple Command 全家桶中的嵌入式迷你语言，负责指令参数内的转义、变量替换、表达式求值、注释与文本格式化。

它不是通用脚本语言。CSC 没有控制流、没有函数定义、没有作用域——它的定位是**表达式语言 + 格式化语言**，用来把一段带变量和表达式的文本，求值成最终字符串。控制流、函数等能力属于未来的扩展层（`SC:More Advanceder CSC`），它们会复用 CSC 的词法、类型系统与错误模型，而不是重新定义一套。

CSC 以独立工程的形式存在，构建产物由 Core **JiJ 内嵌**，因此一个 Core 版本只对应一个 CSC 版本。子模组通过 Core 的封装接口使用 CSC，不直接依赖其内部实现。

## 语言能力概览

- **转义**：`//`、`/n`、`/t`、`/r`、`/%`、`/\`，以及表达式起始标记 `/!`。表达式内外的转义表独立维护，互不影响。
- **注释**：`\注释内容\`，不嵌套；注释内的一切内容不参与解析。未闭合时整段原样输出并记严重错误。
- **变量**：`%name%`，`%` 之间**整体**是一个变量名，可以包含运算符字符（如 `%a*(b+c)%` 是名为 `a*(b+c)` 的变量，不是表达式）。
- **表达式**：`/!(...)`，支持 `+ - * / ** /@`、括号与逻辑运算。幂使用 `**`（Python 风格，右结合），取余使用 `/@`。
- **后缀拼接**：表达式以右括号结束后立刻回到文本模式，后面紧跟的字面字符串与求值结果拼接输出。
- **弱类型**：变量不绑定类型，值有类型；运算中的隐式转换会记录日志，但不打扰玩家。
- **错误分级**：严重错误在聊天栏提示并记录到游戏日志与指令日志；隐式转换仅记录到指令日志。出错片段保留原样，其余部分正常输出。

## 语言示例

```
/!(%a%*(%b%+%c%)/@5)A+B+C
```

这段文本会被解析为：取变量 `a`、`b`、`c` 的值，计算 `a*(b+c)` 对 `5` 取余，再把结果与字面字符串 `A+B+C` 拼接输出。注意表达式在右括号处结束，后面的 `A+B+C` 不是表达式的一部分。

## 设计目标

1. **可预测**：转义、注释、变量、表达式的边界由规范写死，实现与文档一致。
2. **可诊断**：错误与隐式转换有明确的分级和记录位置，便于玩家与管理员排查。
3. **可扩展**：词法与表达式求值器是独立、无副作用的组件，未来的扩展层与脚本运行时可以复用，而不必重写。
4. **可移植**：语言层不依赖 Minecraft 或任何加载器类型，只通过最小接口与外部交互；语言层不做 IO，只产生字符串，输出是调用方的责任。

## 它不做什么

- 不做控制流、函数定义、作用域（属于扩展层）。
- 不做 IO：不写聊天栏、不写日志、不读文件。
- 不认识 Minecraft 类型，也不认识任何加载器。

## 与 Simple Command 的关系

CSC 是全家桶的“粘合剂”：服务器日志的格式化、指令参数中的动态计算、未来脚本运行时的表达式求值，都通过 CSC 统一。因此 **CSC 的语义稳定性优先级最高**——它的行为一旦变化，所有子模组的行为都会受影响。

语言的破坏性变更需要提升版本号并在规范文档里记录，规范与实现不一致时以规范为准。

## 规范与文档

CSC 的完整语法、转义表、运算符优先级、类型规则、错误分级与示例集，以仓库中的语言规范文档 `LANGUAGE.md` 为准。具体 API 说明请参阅源码中的 Javadoc。
